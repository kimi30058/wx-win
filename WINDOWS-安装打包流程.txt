================================================================================
WxAuto 桌面 App（desktop/）Windows 安装环境 + 打包 + 测试 流程与指令
================================================================================
适用对象: 在员工 Windows 电脑上部署「WxAuto 微信自动化桌面 App」的运维/开发人员
对应代码: desktop/（Tauri 2 + Rust + Vue3 + Python sidecar）
对应服务端: Server/src/modules/gateway/channels/wxauto-ws/（WS 网关, 端口 60021）
写成日期: 2026-09-02（2026-09-03 更新: sidecar 已内置安装包, §3 三缺口闭合, 见 §6/§9）


================================================================================
§1 环境清单（打包机 = Windows 真机, 一台机器全搞定）
================================================================================

[必须] 打包/运行基础
  - Windows 10/11, 屏幕缩放 100%（wxautox4 UI 自动化对缩放敏感）
  - Rust（MSVC 工具链）: https://rustup.rs
      安装后确认: rustc --version && cargo --version
  - Visual Studio Build Tools（C++ 桌面开发负载, 提供 link.exe）
      Rust MSVC 工具链链接器依赖它, 缺失则 cargo build 报 "link.exe not found"
  - Node.js ≥ 18 + pnpm:      npm install -g pnpm
  - WebView2 Runtime（Win11 自带; Win10 去 Microsoft 官网装 Evergreen 版）
  - Git

[必须] 微信自动化运行时（真机验收才需要; 仅打包可跳过）
  - 微信 PC 版 4.1.9 ~ 4.1.13.12, 且已登录目标账号
  - Python 3.10+（加到 PATH）
  - wxautox4 ≥ 41.1.1 商业授权（pip 能装, 无授权 check_license() 不过）

[服务端前置]（不由本机承担, 但打包前须就绪）
  - NestJS 服务端已部署, WS 网关端口（默认 60021）从本机可达
  - 服务端 env: WXAUTO_TOOLS_ENABLED=true（16 个 wxauto_* 工具灰度开关, 默认关）
  - 同机多租户共存时服务端须显式配不同 WXAUTO_WS_PORT（详见 Server/.env.example）

§2 拉代码 + 装依赖（打包机一次性准备）
================================================================================

:: 1. 拉仓库（或从内部 Git 拿）
git clone <仓库地址> lyagent
cd lyagent\desktop

:: 2. 前端依赖
pnpm install

:: 3. 补装 tauri CLI —— ⚠ package.json 目前没有 @tauri-apps/cli, 必须先补:
pnpm add -D @tauri-apps/cli

:: 4. Rust 依赖首次编译（顺带验证工具链完整, 首次约 5~10 分钟）
cd src-tauri
cargo check
cd ..

:: 5. Python sidecar 依赖（wxautox4 需授权, 未购买时装不上/跑不了真实模式）
pip install -r sidecar-python\requirements.txt

§6 装机后接线（2026-09-03 起 sidecar 已内置, 免装 Python/pip）
================================================================================

1) sidecar 已冻结进安装包（安装目录下 wxauto-sidecar-x86_64-pc-windows-msvc.exe）,
   Rust 启动时自动探测 exe 同目录的内置 sidecar —— 无须装 Python、
   无须 pip install wxautox4、无须设 WXAUTO_SIDECAR_CMD。
   （开发态仍可用 WXAUTO_SIDECAR_CMD 覆盖; 现支持含空格路径, 引号包裹即可）

2) 登录微信 PC 版（4.1.9~4.1.13.12）, 保持前台已登录

3) 启动 WxAutoDesktop:
   - 「设置」页填服务器地址 ws://<服务端IP>:60021, 粘贴设备 token（§7）, 保存
   - token 存 Windows 凭据管理器（keyring）, 不落明文文件
   - 勾选自动连接则重启 App 即自动连网关

4) 验证闭环: 服务端管理页向该设备发一条 get_my_info 指令, App「日志」页
   应出现指令执行记录且返回 wxid


================================================================================
§7 设备 token 签发（服务端管理操作, 先于装机）
================================================================================

管理端登录后调:
  POST /channels/wxauto/<channelId>/device-token
  （需 channels.write 权限; 渠道必须已存在且 platform=wxauto）
返回一次性明文 token + expiresIn（固定 365d, 当前不可配、无吊销）:
  { "data": { "token": "eyJ...", "expiresIn": "365d" } }
把 token 复制给桌面 App「设置」页。泄漏只能轮换服务端 JWT_SECRET。

§10 常见故障速查
================================================================================

  cargo build 报 link.exe 不存在      → 没装 VS Build Tools, 装「C++ 桌面开发」
  pnpm tauri dev 白屏/连不上 WS      → CSP connect-src 没放行网关地址; 或服务端
                                        WXAUTO_WS_PORT 改过端口, App 设置页同步改
  App 启动即报 sidecar 失败           → 安装目录缺 wxauto-sidecar-*.exe（被杀软
                                        隔离/安装包不完整）; 开发态则查
                                        WXAUTO_SIDECAR_CMD 指向与 python 依赖
  wx.init 返回授权失败                → wxautox4 未授权或授权机器不符, 先跑 §8-B-1
  连上网关但指令全部超时              → 服务端指令超时 60s 无并发上限, 批量慢指令
                                        会拖死后段; 设备端是串行队列, 属已知行为
  装完双击没反应                      → 看 %USERPROFILE%\.wxauto-desktop\ 日志;
                                        WebView2 未装（Win10 老版本）
